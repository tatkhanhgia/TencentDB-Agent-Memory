TDAI Memory — Harness Onboarding

How to connect any coding agent (Claude Code, Cursor, Windsurf, OpenCode, Codex, Grok Build) to the TencentDB Agent Memory system. Written for both humans and agents: every config block is copy-paste ready.

🇻🇳 Tóm tắt nhanh: Kết nối harness vào memory chỉ cần 3 bước — (1) trỏ MCP vào http://127.0.0.1:8425/mcp với token, (2) thêm rules dạy agent gọi tdai_memory_context đầu session, (3) (tuỳ chọn, chỉ Claude Code) gắn hook SessionEnd để tự đúc bài học khi đóng session. Memory là read-only qua MCP — agent không bao giờ tự ghi.

1. Architecture in 30 seconds

READ (live, every session) ┌─────────────┐ MCP Streamable HTTP ┌──────────────────┐ ┌─────────────┐ │ Harness │ ───────────────────────▶ │ MemoryMCP :8425 │ ───▶ │ MemoryCore │ │ (any agent) │ Bearer token │ read-only tools │ │ :8420 │ └─────────────┘ └──────────────────┘ │ L0→L1→L2→L3 │ │ └─────────────┘ │ WRITE (only at session end, only via hook) ▲ └── SessionEnd hook ──▶ tdai-reflect CLI ── extracts ≤3 lessons ─────┘ (writing nothing is the normal outcome)
  • Reads go through a read-only MCP server. Four tools, nothing can mutate memory.
  • Writes happen only when a session ends: a hook runs tdai-reflect, which extracts at most 3 durable lessons (ADRs, constraints, preferences) — or, most of the time, nothing. Agents must never write memory directly.
  • Memory layers: L0 raw lessons → L1 atomic memories → L2 scene files → L3 persona. Consolidation is automatic. All outputs are always English.

2. Step 1 — Point your harness at the MCP server

Get the device token

There is exactly one kind of token: a device token, declared in deploy/global-images/.mcp.bindings.json (bootstrapped automatically on first ./start-memory-mcp.sh run, and printed by that script). By default a token declares "identities": "registry" — the identity list resolves live from the Panel agent registry, one identity per agent/project. A static identities: [...] array pins the list instead. Per session:

  • Several identities, no "default" → the first memory tool call of a session shows the user a native picker (MCP elicitation). Clients without elicitation get the tdai_identity_use fallback tool instead.
  • "suggested": "<name>" → that identity comes preselected in the picker, so accepting the usual choice is a single Enter (you are still asked).
  • One identity, or "default" declared → the session binds silently, nothing to pick.

Adding an agent/project later means editing this one server-side file — harness configs never change. (Single-purpose tokens hard-bound in .mcp.env were removed: coding harnesses serve many projects, so a fixed binding is wrong by default.)

Two things agents often miss: (1) MCP configs are read at session start — after writing the config, the current session cannot use it; open a new session. (2) A brand-new long-lived project should usually get its own agent (see §5 "Adding a new agent/project") instead of piggybacking on an existing identity; reusing the device token's existing identities is for shared/personal machine-wide memory.

3. Step 2 — Teach the agent to use memory (rules)

Append this to the harness's rules file (never replace existing rules) — CLAUDE.md, AGENTS.md, .cursorrules, .windsurfrules… Ready-made snippets: examples/rules/.

# TDAI memory (read-only)
At session start, call `tdai_memory_context` once to load team memory
before non-trivial work.
When a task references past decisions or conventions, use
`tdai_memory_search` (and `tdai_scene_read` for the full scene) before
re-deriving from scratch.
Do not write memory yourself. Capture runs automatically at session end
via a hook, not the model.
Do not dump memory contents verbatim into files or commits.

4. Step 3 (optional) — Enable the write path

Only Claude Code has a SessionEnd hook today. Other harnesses stay read-only, which is fine.

// .claude/settings.json (project) or ~/.claude/settings.json (global)
{
  "hooks": {
    "SessionEnd": [
      { "hooks": [ {
        "type": "command",
        "command": "/Users/mac/Documents/Projects/MyProjects/TencentDB-Agent-Memory/deploy/global-images/hooks/tdai-reflect-hook.sh"
      } ] }
    ]
  }
}
  • The hook is fire-and-forget (always exits 0, runs detached). Log: deploy/global-images/.reflect.log.
  • Sessions shorter than 6 text turns are skipped. Extraction uses the local LLM (LM Studio, 127.0.0.1:1234) — it must be running with the model loaded, or the hook logs an error and writes nothing.
  • Writes are idempotent: re-running reflect on the same session never duplicates lessons.
  • Per-project write identity — resolved automatically, in priority order:
    1. .tdai-project.env at the project root (explicit override; sync-memory-identities.sh --link writes it, or any agent can from the write_routing info returned by tdai_identity_use).
    2. Folder-name convention (zero setup): an active registry agent whose slugged name matches the project folder name — name the Panel agent after the project folder and writes route themselves.
    3. The machine default agent from .mcp.env.
    Reads follow the session's picker choice; writes follow this resolution. The .reflect.log line shows which route was used (route=file|folder-name:…|default).

5. The identity model (what the picker is about)

Every memory record is isolated by team / user / agent. There is no "project" dimension — one project = one agent. A session reads exactly one agent's store, chosen once:

  1. Token maps to one identity (or declares "default") → binds silently. Done.
  2. Token maps to several identities → the first memory tool call asks the user to pick, via a native dialog (MCP elicitation — Claude Code interactive supports this).
  3. Client without elicitation (headless runs, some IDEs) → the tool call returns identity_not_selected with the list; the agent calls tdai_identity_use {"name": "..."} — and should ask the user which one if unclear. Switching mid-session with the same tool is allowed.

Adding a new agent/project later

  1. Create the agent in the Panel (http://127.0.0.1:8125) — that's it for reads: with "identities": "registry" the new agent appears in every harness's picker within ~30 seconds (registry cache TTL). No commands, no config changes.
  2. To also write that project's lessons into its own store, run deploy/global-images/sync-memory-identities.sh --link <project-dir> <agent-name> once — it writes the project's .tdai-project.env (see the write path below).
  3. Static-list bindings only: run sync-memory-identities.sh (optionally --prune) to pull the registry into the pinned list.

6. Tool reference

ToolWhat it doesWhen the agent should call it
tdai_memory_contextOne-shot recall bundle: persona + scene index + top matching atoms.Once at session start, before non-trivial work.
tdai_memory_searchTargeted search over L1 atomic memories (filter by type, time).When a task touches past decisions or conventions.
tdai_conversation_searchSearch raw L0 lesson records across sessions.When atom-level answers aren't enough and provenance matters.
tdai_scene_readRead one L2 scene file by path. Accepts the scene_blocks/-prefixed paths shown in the persona scene index.To read the full SOP behind a scene-index entry.
tdai_identity_list *List identities this session may act as, and which is active.Only after an identity_not_selected error. * Present only on multi-identity tokens.
tdai_identity_use *Bind the session to one identity by name.

7. Troubleshooting

SymptomCause → fix
Connection refused on :8425Server not running → cd deploy/global-images && ./start-memory-mcp.sh (also part of start-all.sh). Health check: ./start-memory-mcp.sh --status.
401 unauthorizedWrong/missing Bearer token → re-read the token from .mcp.env / .mcp.bindings.json (it is regenerated only if deleted).
identity_not_selected errorNormal on multi-identity tokens without a default — pick via the dialog, or call tdai_identity_use. Not a failure.
Session not found / re-initializeThe MCP server restarted (sessions are in-memory, 60-min idle expiry) → the client reconnects automatically on the next call.
Hook ran but no lessons appearCheck .reflect.log. "skipped" = session too short or nothing durable (normal). LLM timeout = LM Studio not running/slow — the hook allows 240s by default.
stdio server exits immediatelyMissing env → the wrapper needs .mcp.env filled in and MemoryCore running (it falls back to .admin-key for the API key).
Sanity check for a new setup: open a fresh session and ask the agent "what do you remember about this team's architecture decisions?" — it should call tdai_memory_context (picking an identity if asked) and answer from memory, not from guesswork.
