1 Bức tranh tổng thể

Bạn không “cài memory vào trong Claude Code”. Bạn chạy một stack local, rồi bảo Claude Code: “hãy gọi API ở máy tôi”.

Bạn + Claude Code CLI

2 Vì sao có 2 nhóm LLM trong .env?

Không phải “phải chạy 2 model”. Là 2 vai trò — trên máy bạn cả hai đều trỏ về cùng Gemma.

PROXY_UPSTREAM_*

Ai gọi: MemoryProxy

Khi nào: mỗi tin nhắn Claude Code cần model trả lời

Output: câu trả lời hiển thị trong terminal Claude Code

→ host.docker.internal:4000/v1

MEMORY_LLM_*

Ai gọi: MemoryCore / Hub (nền)

Khi nào: extract fact, tóm tắt scene, persona, wiki…

Output: memory assets trong DB / panel — không phải chat UI

→ host.docker.internal:4000/v1

Vì sao tách config? Production thường: chat dùng model mạnh/đắt, extract dùng model rẻ. Local: gán cùng một endpoint cho cả hai là ổn.

3 Một lượt chat đi đâu?

Ví dụ bạn gõ: “Nhớ giúp: tôi thích TypeScript strict”.

  1. Claude Code gửi request Protocol Anthropic POST .../v1/messages tới http://127.0.0.1:8096/claude-code/default, kèm sk-mem-....
  2. Proxy xác thực + session Đổi key → user. Lần đầu có thể hỏi Team / Agent / Task (Local Coding Team → coder → default-task). Các lượt sau nhớ binding.
  3. Proxy inject ngữ cảnh Nhét L2/L3 memory, skill tools, hướng dẫn memory-search vào system prompt (nếu đã có dữ liệu; lúc đầu gần như trống).
  4. Forward sang model local Proxy → LiteLLM (:4000) → LM Studio (:1234) → Gemma sinh câu trả lời → ngược về Claude Code.
  5. Ghi nhớ nền Proxy gửi slice hội thoại về MemoryCore (L0). Pipeline sau đó có thể rút L1/L2/L3 (cũng bằng MEMORY_LLM = Gemma).
  6. Bạn kiểm tra trên Panel Mở http://localhost:8125 → Chat Memory / Agent profile.

5 Cái gì là UI / CLI / nền?

UI Panel :8125 ← kiểm tra memory, team, skill
CLI Claude Code ← chỗ bạn code / chat hàng ngày
Core + Proxy + LiteLLM + LM Studio ← hạ tầng (Docker + app local), không cần mở từng cái mỗi ngày
Không có “dashboard model training”. UI chính là Panel. Chat thật nằm ở Claude Code. Model local quản lý trong app LM Studio.

7 Một câu để nhớ

Claude Code = mặt trước. Proxy = trung gian nhớ + inject. Core = kho nhớ. Panel = kính soi kho nhớ. LM Studio = não sinh text (1 model). LiteLLM = phiên dịch protocol.

Mục tiêu triển khai: coding agent không sửa code vẫn được tự inject / tự ghi nhớ — vì mọi request đi qua proxy.
